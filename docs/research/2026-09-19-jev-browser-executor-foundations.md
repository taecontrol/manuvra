# Foundations for a Jev-driven browser flow executor in Rust

## Question, context, scope, bound, date

**Date:** 2026-09-19. **Role of this document:** judge's synthesis of two independent research drafts (A and B) against the brief in `scratchpad/research/brief.md`, after re-checking the sources behind every decisive or disputed claim.

**Context.** manuvra is being restarted as a browser flow executor: a coding agent hands it a JSON job `{url, ordered steps with done conditions, named values, expectations}`; the tool drives a dedicated Chromium over loopback CDP and asks TypeSafe's Jev (System One: Choice/Score/Noul over text state, no generation) to pick, per observation, one operation and one target from an indexed element table. Typed values come only from the caller; Jev only selects which named value goes where. Output per step: verdict, expectation probabilities, evidence (snapshots, screenshots). Linux (Wayland/Hyprland, Chromium 152) first, macOS later. Rust 1.98 toolchain; workspace `rust-version = "1.95"`, edition 2024.

**Scope.** Five questions: (1) CDP from Rust, (2) calling TypeSafe from Rust, (3) prompting Jev for action selection, (4) observation source, (5) typing strategies. Reference implementation: `browser-use/jev-ultrafast` at commit `1231850a0bf1a0c0341fe408ef1668dbbfdfac46`. Existing crate: `crates/manuvra-chrome` at workspace commit `9e22e28` (0.2.3).

**Bound.** Desk research only. Nothing was built, compiled, or benchmarked; binary-size and compile-time statements are proxies. Two researchers worked about 60 minutes each; the judge re-fetched or re-read the load-bearing sources (listed under Method and Sources).

## Direct answers

**Q1. CDP from Rust.** Keep and extend manuvra-chrome's own transport; do not adopt `chromiumoxide` or `headless_chrome` as the driver. The crate already issues every method the brief lists (`Runtime.evaluate`, `Runtime.callFunctionOn`, `Input.dispatchKeyEvent`, `Input.insertText`, `Input.dispatchMouseEvent`, `Page.captureScreenshot`, `Page.getFrameTree`, `Accessibility.getFullAXTree`, `DOM.describeNode`/`resolveNode`/`getBoxModel`, `Page.navigate`) and has an event journal plus `NotSent`/`Unknown` mutation semantics that neither crate offers. Whether to port the socket from blocking `tungstenite 0.28` to `tokio-tungstenite 0.30` is a runtime-placement decision, not a fact either draft could settle; the process already runs tokio (`manuvra-cli`, `manuvra-runtime`), so the port costs nothing in dependencies but is not required for v1 (see Disagreements). Runner-up if the design ever needs many domains or helpers: `chromiumoxide 0.9.1` (tokio-only, full generated protocol, 7 months since last release).

**Q2. Calling TypeSafe from Rust.** `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer <key>`, JSON body `{model, state, questions}`; response `{model, answers, usage}`. Errors 401/422/429/529; retry with exponential backoff. Replicate the SDK retry policy: 2 retries, 0.5 s initial doubling to 5 s cap, 25 % jitter, retry on 408/429/500–599 and on connection/timeout errors, honour `Retry-After`/`retry-after-ms` (JS caps at 60 s), 10 s per-attempt timeout, plus an overall deadline (Python's 30 s budget). Client: `reqwest 0.13.5` if the executor runs on the tokio runtime already in the process; `ureq 3.4.2` if it is a blocking thread. Hand-written serde models; copy jev-ultrafast's `validate_choice` in code (choice among offered ids, probability keys equal offered ids, finite 0–1, sum within 0.02 of 1, choice is argmax). Pin `jev-1.13.0` once thresholds are tuned.

**Q3. Prompting Jev.** One request per observation with speculative heads: `operation` (Choice), one `<op>_target` Choice per available operation, a value-selection Choice over caller value names plus `none`, and Nouls for the step's done condition and each expectation. Every head restates its premise because heads cannot read each other. Criteria are structured objects carrying `current_value`, checked/selected/expanded; state is `{page:{url,title,text}, elements[], recent_actions[], plan:{current step only, completed steps as facts}}`. Comparisons, counting, dates and format selection happen in code. Gate on per-head `confidence` with thresholds that scale with risk and are tuned on recorded runs; confidence on a Noul and on a Choice are not comparable. jev-ultrafast itself does not gate on confidence; it relies on structural validation, freshness guards, budgets and a "three non-wait actions without page change" rule.

**Q4. Observation source.** Injected DOM snapshot as the primary indexed table (jev-ultrafast lineage: WeakMap identity, visible controls, current values, freshness guards, single `Runtime.evaluate`), upgraded with Playwright-style accessible-name computation and open-shadow-root/slot traversal, and a hybrid CDP fallback: resolve the chosen live node to a `backendNodeId` via `DOM.describeNode{objectId}` and use `Accessibility.getPartialAXTree{backendNodeId}` for name cross-checks and evidence. Do not use `Accessibility.getFullAXTree` as the per-decision input (whole domain experimental; needs per-frame calls and extra geometry calls). Both drafts agree; the judge confirms the underlying facts.

**Q5. Typing.** "What": job carries `values: {name: {value, description, formats?, secret?}}`; Jev answers a Choice over value names + `none`; `none` or low confidence yields a `missing_value` verdict, never a guessed string. No surveyed tool restricts the model this tightly; Stagehand's `%var%` and browser-use's `sensitive_data` are the nearest prior art. "How": real click on the hit-tested centre, `Input.dispatchKeyEvent{keyDown,key:"a",code:"KeyA",modifiers:2|4,commands:["selectAll"]}` + keyUp, then `Input.insertText{text}` (Playwright `fill` and jev-ultrafast path), then read back `value`. Native setter + `input`/`change` only for `color/date/time/datetime-local/month/range/week` and `<select>`. Comboboxes: type, wait up to 200 ms for a visible `[role=option]`, re-observe, and let the next decision CLICK the suggestion; never synthesize Enter. Per-key `dispatchKeyEvent` is an explicit fallback, not the default; the judge found that Chrome DevTools MCP (via Puppeteer `Locator.fill`) actually types per key for values under 100 characters, which strengthens the case for keeping the fallback.

**CDP protocol facts (judge re-read `browser_protocol.json`, version 1.3, fetched 2026-09-19).** `Input.insertText` is experimental; `Input.dispatchKeyEvent` is stable but its `commands` parameter is experimental; the entire `Accessibility` domain is experimental (`getFullAXTree{depth?, frameId?}`, `getPartialAXTree{nodeId?|backendNodeId?|objectId?, fetchRelatives?}`, `queryAXTree`); `DOMSnapshot` domain experimental; `DOM.describeNode`, `DOM.resolveNode`, `DOM.getBoxModel`, `DOM.scrollIntoViewIfNeeded`, `DOM.getDocument{pierce}` are stable; `DOM.getContentQuads` experimental; `Emulation.setFocusEmulationEnabled` experimental; `Target.attachToTarget{flatten}`, `createTarget`, `setAutoAttach` stable. `AXNode` carries `nodeId, ignored, role, name, value, properties, parentId, childIds, backendDOMNodeId, frameId`.

**Assessment.** Both drafts independently reached "keep the own transport"; the judge confirms the supporting facts. The decisive ones are (a) the needed surface is a dozen raw methods already exercised and tested, (b) journal + `NotSent/Unknown` semantics are not offered by either crate, (c) both crates own and kill their child process, contradicting the never-kill launch policy (`launch.rs:96-99`), (d) both crates' typing helpers are per-key and would be bypassed anyway, (e) `Accessibility`/`DOMSnapshot` are experimental, which favours raw JSON over generated types pinned to a protocol revision. ### Q2. Calling TypeSafe from Rust

All contract facts below were re-read by the judge in the cached `.md` pages (`scratchpad/research/src/`), which are verbatim fetches of `https://docs.typesafe.ai/...md` made 2026-09-19.

- Endpoint and auth: `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer <API_KEY>` — `api.md:14-15`.
- `model`: required; `jev-latest` → `jev-1.13.0`; `jev-preview` currently the same — `models.md:11, 33-37`. "If you have tuned confidence thresholds against a specific version, pin that version's ID instead of the alias" — `models.md:40`. `GET /v1/models` exists and lists aliases; versioned IDs are accepted whether or not listed — `models.md:60` (this settles Draft B's "[inference]" on the path: it is documented).
- `state`: "must be a string, JSON object, or array of text values" — `concepts/state.md:32`.
- Choice: up to 255 options; "Add an `other` or `none of the above` option" — `primitives/choice.md:355`.
- Response: `{model, answers, usage:{input_tokens, output_tokens}}`; answer shapes `{type:"noul", noul}`, `{type:"choice", choice, probabilities, confidence}`, `{type:"score", score, legend, probabilities, confidence}` (both drafts; `api.md` and JS SDK interface pages; not disputed).
- Limits: 250,000 tokens/s and 1,200 requests/min; 64k tokens per request; 32k for `state` plus the longest question; $0.042/Mtok input — `models.md:13-15, 20`. "Rate limits are adjusting dynamically … can change without notice" — `models.md:24`.
- Errors: 401, 422 ("The body details the offending field"), 429, 529 — `api.md:316-319`; "retry the request with exponential backoff instead of retrying immediately" — `api.md:323`.
- Python `RetryPolicy` defaults: `max_retries=2`, `backoff_initial=0.5`, `backoff_max=5.0`, `backoff_jitter=0.25`, `http_statuses={408, 429, *range(500,600)}`, `respect_retry_after=True`, `api_connection_error=True`, `api_timeout_error=True`, `timeout=30.0` ("Total retry budget in seconds per SDK call … Stops before a retry whose delay would reach or exceed the budget") — `sdk/python/api/retries.md:45, 272, 352, 428-430`. `DEFAULT_TIMEOUT = 10.0` "for each HTTP operation" — `sdk/python/api/constants.md`. Env vars `TYPESAFE_API_KEY`, `TYPESAFE_BASE_URL` (default `https://api.typesafe.ai`), `TYPESAFE_DEFAULT_MODEL` (`jev-latest`), `TYPESAFE_LOG_LEVEL` — same page.

- Headers: `x-typesafe-request-id`, `Retry-After`, `retry-after-ms` (both drafts, from the SDK error classes). No documented quota-remaining headers.
- jev-ultrafast's client: `httpx.Client(http2=True, timeout=25)`, 3 attempts, retry on `{429, 529, 503}` with `0.5 * 2**attempt` sleep, connection errors not retried — `jev_ultrafast/model.py:12-27`; `validate_choice` — `model.py:30-45` (judge-verified; Draft A's line numbers for this file were wrong, see Method).
- Client crates (crates.io, judge-verified): `reqwest 0.13.5` (2026-09-08), `ureq 3.4.2` (2026-09-13).

**Serde model (both drafts converge; judge endorses).** `#[serde(tag="type", rename_all="lowercase")] enum Question { Noul{instructions: Value, criteria: Option<NoulCriteria>}, Choice{instructions: Value, criteria: IndexMap<String, Value>}, Score{instructions: Value, criteria: Vec<Value>} }`; `Request { state: Value, model: String, questions: IndexMap<String, Question> }`; `enum Answer { Noul{noul: f64}, Choice{choice: String, probabilities: HashMap<String,f64>, confidence: f64}, Score{score: f64, legend: HashMap<String,String>, probabilities: HashMap<String,f64>, confidence: f64} }`; `Response { model, answers: HashMap<String, Answer>, usage }`. Keep `Value` for `instructions`/`criteria` entries (the docs allow string, object, array, and `null`), keep a fallback for unknown answer `type`, and capture the raw 422 body since its schema is only described as "details the offending field".

### Q3. Prompting Jev for action selection

**From TypeSafe's guidance (judge re-read the cached pages).**
- One request, independent heads: "putting all of the questions your system needs in a single request … All questions are evaluated in parallel, so adding more questions to a call typically doesn't add any latency" — `patterns/fan-out.md:238`. "Questions in the same request are independent: one answer does not become context for another question. If a later judgment depends on an earlier answer, make a second request in code. The dependency is real only when your code cannot build the second request until it has the first answer" — `primitives.md:458`. Batching 13 questions: "12.2x cheaper, 10.0x faster" (`cookbooks/parallel_questions.md`, judge-fetched) vs "11.5x cheaper and 9.6x faster" quoted in `primitives.md:442` — the two doc pages disagree on the exact figure; the order of magnitude is what matters.
- Criteria: "describe what belongs in each option, what belongs in a neighboring option instead, and a few representative examples. Use the same field names across options" — `concepts/how-to-build-with-system-one.md:669` (examples use `not_for`, lines 689-808). Backticked paths to nested state, e.g. `` `support.tickets[0].message` `` — same page, 348-351.
- Select, don't generate: "when the answer space is bounded, turn extraction into a Choice over the options rather than asking for the value itself" — `model-jaggedness/jev-1.13.md:143`. Pre-parsed extraction: "The options ARE the candidate spans, so `choice` is a verbatim copy of one of them (or the `none` hatch) - the model chooses, code owns the string"; "It cannot invent a value or transpose a digit" — `cookbooks/pre_parsed_value_extraction_cookbook.md:26, 100-101`.
- Function calling: `stated` Noul "makes an argument optional" — `cookbooks/function_calling.md:158`; "`confidence` reports the least certain judgement in the call, rather than the product" — `:319` (Draft B's use is accurate: combine heads with a minimum, not a product).
- Confidence: "derived from the probabilities"; "a flatter distribution means lower confidence" — `confidence.md:13-21`; "Thresholds scale with risk"; "Start with conservative thresholds, test with your own data" — `confidence.md:41-83`. Worked example: `< 0.6` route to a human, `> 0.85` to auto-approve a transfer — `patterns/confidence-routing.md:269-289`.
- Jaggedness (`model-jaggedness/jev-1.13.md`): literal reading (29), no counting (41), numeric representations (66), dates "Extract components; compare in code" (21, 84), indirection (88), "Accuracy falls as the state grows with content unrelated to the decision" (96), adversarial content "can move the answer" (106), contradictory instructions vs criteria (110), no structural invariants across questions — "Ask each decision one way; enforce identities in code" (26, 116), no generation (139).
- Two-stage selection for large rosters: 182 skills in one Choice, top three re-judged, 0.30 mean-Noul gate — `cookbooks/skill_suggestion.md:7, 124-129`.

**From jev-ultrafast (judge re-read; line numbers are the judge's).**
- Request shape: `operation` Choice with criteria `{CLICK, TYPE_TEXT, SELECT}` (only those with candidates) plus observed page controls plus `DONE`/`BLOCKED`; one `<op>_target` Choice per available operation with criteria `{element:"[i] label", current_value, role?, checked?, selected?, expanded?}` and instructions `{goal, operation, rules:[NEXT_ACTION, TARGET]}`; state `{page:{url,title,text}, elements, recent_actions: last 10 of {action, kind, text, page_changed}}` — `jev_ultrafast/model.py:81-117`. Only the head matching the chosen operation is validated and consumed: "Unused target heads cannot cause an action" — `model.py:126`.
- Rules text — `questions.py:3-14` (NEXT_ACTION) and `16-19` (TARGET: "another question decides which operation to execute. Do not choose a field that already contains the requested value. Choose only an offered element index").
- Design rationale: "a target cannot read the operation answer, so its premise explicitly names the operation it assumes" — `docs/design.md:7`; "These IDs are not CDP backend node IDs. Geometry is always read again immediately before input" — `design.md:13`; "A valid action can still be wrong. Independent checks, rather than the model's DONE choice, determine whether the demonstrated task succeeded" — `design.md:33`.
- No confidence gating: confidence is recorded (`agent.py:128`) but stop conditions are budgets (`MAX_STEPS = 60`, `questions.py:26`; 120 decisions, `design.md:31`) and three consecutive non-wait actions without page change → blocked (`agent.py:155-156`).
- Text generation by a separate LLM (`TYPE_TEXT` → `field_text`, `model.py:160-198`; `TEXT_VALUE`, `questions.py:21-24`) — the thing the brief forbids.
- Measurements: 17 Jev requests, median Jev latency 178 ms (`docs/performance.md:28`); protocol calls 1,092 → 101 and "Three pairs are too few for a strong statistical claim" (`performance.md:18`).

**Rules for manuvra's question design (synthesis; items marked (inference) are the judge's).**
1. One request per observation with fixed speculative heads: `operation`, `click_target`, `type_target`, `select_target`, `value_for_type` (Choice over caller value names + `none`), `step_done` Noul, one Noul per expectation. Consume only heads consistent with the chosen operation; validate every consumed head structurally (jev-ultrafast `validate_choice`).
2. Every head restates its premise and receives the same rules block (`design.md:7`; `questions.py:16-19`).
3. Jev never emits text: `TYPE_TEXT` resolves to `(element index, value name)`; code copies the caller string (pre-parsed extraction pattern).
4. State: visible text only, indexed element table with `current_value` and states, `recent_actions` capped, plus `plan:{current_step:{index, instruction, done_when}, completed_steps:[…]}`. Keep future steps and the full job out of state (large-state jaggedness, `jev-1.13.md:96`). (Inference, shared by both drafts: the exact plan-context shape is untested.)
5. Criteria as structured objects with the same field names; `none`/`BLOCKED` hatches everywhere (`choice.md:355`).
6. Comparisons, counting, dates and "already filled" checks are computed in code and expressed as facts in state or by removing options; never asked of Jev (`jev-1.13.md:21-41, 84`).
7. Gate per head with risk-scaled thresholds; combine `type_target` and `value_for_type` with a minimum, not a product (`function_calling.md:319`); do not compare Noul values with Choice confidences (`jev-1.13.md:116`). Draft B's starting points (CLICK ≥ 0.5, TYPE ≥ 0.6 on both heads, DONE Noul ≥ 0.85) are consistent with the docs' worked example but are untuned; treat as placeholders to calibrate on recorded runs, and pin `jev-1.13.0` once tuned (`models.md:40`).
8. Below the floor: re-observe once (WAIT), then BLOCKED with distributions attached (both drafts). Independent verification of done conditions in code, never trusting a DONE choice (`design.md:33`).
9. Cap options at 255 per head; pre-filter by role or use two-pass selection when exceeded (`choice.md:355`, skill-suggestion cookbook).
10. Log request, answers, usage, `x-typesafe-request-id`, latency per decision (jev-ultrafast records `raw_answers`, `latency_ms` — `model.py:143-146`).

### Q4. Observation source

**Injected snapshot (jev-ultrafast `snapshot.js`, 107 lines; judge-verified lines).** `window.__jevFast = {ids: WeakMap, nodes: Map, next}` (3); disconnected nodes pruned each snapshot (8); `checkVisibility({checkOpacity, checkVisibilityCSS})` (11); accessible-name approximation `aria-labelledby` → `aria-label` → labels → … → `title`/`placeholder` (15-22); roles list incl. `combobox, textbox, searchbox, spinbutton, gridcell, option` (25); `gridcell` skipped when it contains a button (60); visible text and scope text capped at 6000 chars (53, 84, 92); `pageKey` (44), per-target `guard` (47-53), `marker` (97). Execution recheck: connected, not disabled/inert, visible, not readOnly for fill, geometry re-read, `elementFromPoint` occlusion test, then real mouse events — `browser.py:144-169`. Stated limits: "does not implement the full accessible-name algorithm or traverse shadow roots/frames" — `docs/performance.md:55`; `design.md:33`.

**Playwright aria snapshot (`packages/injected/src/ariaSnapshot.ts`, cached copy).** Walks `shadowRoot` children and slot `assignedNodes` (172-182); emits `role: 'iframe'` nodes with refs and `iframeRefs`/`iframeDepths` so the host recurses per frame (146-147, 239, 464-470); refs stored as `element._ariaRef` and reissued only when role or name changes (`computeAriaRef`, 220-230); `refs: 'interactable'` drops non-visible/non-pointer nodes (223). Playwright MCP exposes this as `browser_snapshot` ("better than screenshot") — README.

**CDP AX tree.** Whole `Accessibility` domain experimental (`browser_protocol.json`); `getFullAXTree{depth?, frameId?}` per frame; nodes carry `backendDOMNodeId` but no geometry, so each chosen node needs `DOM.getBoxModel`/`DOM.scrollIntoViewIfNeeded` before acting. browser-use joins `Accessibility.getFullAXTree` per frame + `DOMSnapshot.captureSnapshot{includeDOMRects}` + `DOM.getDocument{depth:-1, pierce:true}` on `backendNodeId` — `browser_use/dom/service.py:379, 571-584, 791-812` (cached copy). Chrome DevTools MCP uses Puppeteer `page.accessibility.snapshot()` and keys uids as `${loaderId}_${backendNodeId}` — `src/TextSnapshot.ts:56-89` (cached copy). manuvra-chrome today: `Page.getFrameTree` → `Accessibility.getFullAXTree` per frame (`page.rs:658-684`) plus `DOM.getBoxModel` per target (`page.rs:932`).

**Stability claim.** Both identity schemes (WeakMap id, `backendNodeId`) are per DOM node: a React re-render that patches a node in place keeps the id; a remount changes it. Both drafts state this; it follows from the definitions rather than from a measured source (inference, shared). Whether the AX tree flattens open shadow DOM is asserted by both drafts as an inference and was not verified by anyone.

**Recommendation and reasoning.** Injected snapshot primary (one round trip gives controls, values, text, and live handles for safe execution; measured 10× fewer protocol calls in jev-ultrafast's small comparison), extended with Playwright-style name computation and open-shadow/slot traversal, same-origin iframes by injecting per frame (`Page.getFrameTree` + `Runtime.evaluate{contextId}`), cross-origin iframes surfaced as `iframe` elements in v1. Hybrid fallback: after selection, `DOM.describeNode{objectId}` (stable) to obtain `backendNodeId` for screenshots/highlights and `Accessibility.getPartialAXTree{backendNodeId, fetchRelatives:false}` as a name cross-check and evidence, or only when the script yields an empty/ambiguous name (Draft A) — the two variants differ only in when the call is made, and telemetry from real runs should decide. Keep `backendNodeId` out of the identity path (`design.md:13`).

### Q5. Typing strategies

**"What" to type — survey (judge re-verified the starred rows).**
- jev-ultrafast: separate LLM writes the value; `{"text": null}` → `ValueError("Text helper returned no valid field value; nothing typed.")` — `model.py:160-193`, `questions.py:21-24`. *

**Why `insertText` works with React controlled inputs.** Both drafts infer it; the direct evidence is (a) browser-use's comment that direct `.value=` assignment defeats React's value tracker, (b) Playwright's choice of `insertText` for text types and setter+events only for structured types, (c) jev-ultrafast running on Google Flights with `insertText`. No source states the mechanism explicitly; the judge keeps it as a well-supported inference and lists the `beforeinput`/`inputType` behaviour on Chromium 152 as an item for a spike.

**Recommendation.**
1. Job schema `values: {name: {value, description, formats?: {iso, display}, secret?}}`. State shows names and descriptions, and the literal for short non-secret values (helps "already filled" detection and label matching); secrets never enter state. Jev answers `value_for_type` (Choice over names + `none`), consumed only when `operation == TYPE_TEXT`; `none` or sub-threshold → `missing_value` verdict with the field label as evidence.
2. Format selection is code: `input.type ∈ {date, time, datetime-local, month, week}` → `formats.iso` via native setter + `input` + `change`, verify `value === expected` else `malformed_value`; text-like → `formats.display ?? value`.
3. Text-like fields: hit-tested click → select-all (either `commands:["selectAll"]` or manuvra-chrome's existing `this.select()` via `Runtime.callFunctionOn`; the latter avoids the experimental `commands` parameter but does not cover `contenteditable`, so keep both) → `Input.insertText` → read back `value` via `Runtime.callFunctionOn`. On mismatch, one retry via native setter + `input` event (Skyvern/browser-use prior art), then `typed_mismatch`.
4. Per-key `dispatchKeyEvent` (keyDown/char/keyUp) as an explicit fallback for fields with `aria-autocomplete` or when insertText produced no suggestions; capped by length. This is what Playwright MCP `slowly`, browser-use, and (via Puppeteer) Chrome DevTools MCP do by default, so it is not exotic.
5. Comboboxes: type, wait ≤200 ms for visible `[role=option]`, re-observe, next decision CLICKs the suggestion; never synthesize Enter. Radix/ARIA listbox and menu widgets, date-picker grids, checkboxes/radios/switches: CLICK only; exclude the visually hidden native `<select>` Radix renders (visibility filter).
6. Native `<select>`: SELECT operation with `index:option` targets, executed in-page via `value=` + `input` + `change`; verify `selectedIndex`.
7. Never retry a browser mutation blindly ("Never retry a browser mutation" — jev-ultrafast `AGENTS.md:9`; manuvra-chrome `Unknown` outcome); re-observe and decide again.
8. Evidence: pre/post `value`, chosen value *name*, `x-typesafe-request-id`, screenshot after read-back.

## Contrary evidence, disagreements, and resolution

**Shared-source dependence.** Both researchers built Q2 and Q3 almost entirely on the TypeSafe docs and Q3/Q4/Q5 heavily on jev-ultrafast. Agreement between the drafts on those points is therefore *not* independent corroboration; it is two readings of the same source. The judge re-read those sources rather than counting votes. Independent corroboration exists for: the insertText-for-text / setter-for-structured-types split (Playwright source, jev-ultrafast, browser-use clearing comment, Skyvern's Malformed-value handling), the combobox "click the suggestion, never Enter" rule (jev-ultrafast rules, browser-use hint, Chrome DevTools MCP's combobox-as-select branch), and the placeholder-substitution pattern (Stagehand, browser-use).

**1. Sync `tungstenite` vs port to `tokio-tungstenite` (A: keep sync; B: port).** Facts: the transport is blocking on a worker thread (`transport.rs`); `tokio` is already compiled into the process via `manuvra-cli/src/daemon.rs` and `manuvra-runtime` (judge-verified), so B's "share one runtime" is cheap in dependencies, and A's "adding tokio only to drive one WebSocket" mischaracterises the workspace. Neither draft has evidence that the port yields a benefit for a sequential observe → decide → act loop; the blocking worker thread already coexists with tokio via channels. **Resolution:** not a factual dispute. Keep the blocking transport unchanged for v1 (1,157 lines plus 775 lines of tests already pass; porting is pure cost until concurrency is needed); revisit when the executor needs concurrent jobs or the Jev call and CDP waits must overlap. The journal and `NotSent/Unknown` semantics port unchanged either way.

**2. `ureq` vs `reqwest`.** Both are current (`ureq 3.4.2` 2026-09-13; `reqwest 0.13.5` 2026-09-08). The choice follows from where the executor loop runs: inside tokio (already present) → `reqwest` with rustls + HTTP/2 and one pooled `Client`; on a blocking thread → `ureq`. **Resolution:** conditional; if disagreement 1 is resolved as "keep sync", `ureq` is the consistent pick unless the executor is hosted inside the existing daemon's runtime, in which case `reqwest`. Either way the retry loop is hand-written (~40 lines) because `reqwest-retry` does not read `retry-after-ms` (B; not re-verified).

**3. Role of per-key `dispatchKeyEvent`.** Both drafts make `insertText` the default and per-key an opt-in fallback; the judge confirms the primary sources. The contrary evidence is stronger than either draft stated: browser-use types per key by default, Playwright MCP offers `slowly`, and Chrome DevTools MCP (through Puppeteer `Locator.fill`) types per key for values under 100 characters, falling back to direct value assignment above that — not insertText (judge finding; Draft B's inference was wrong). **Resolution:** keep `insertText` default (single CDP call, replaces content, Playwright's production path) with per-key as an explicit fallback that must exist from v1 because three of the surveyed tools rely on key handlers firing.

**4. Comboboxes.** Both drafts converge on: type → bounded wait for visible `[role=option]` → re-observe → CLICK the suggestion; no Enter. Independent corroboration from browser-use (`sleep(0.4)`, hint text) and jev-ultrafast (`≤200 ms`, rule text). Chrome DevTools MCP adds a third pattern: when the AX node is `role=combobox` *with option children* it is handled as a select (`input.ts:250-253`). **Resolution:** adopt the two-phase flow; add the DevTools-MCP distinction so that a combobox that already lists its options (Radix Select, ARIA listbox) is CLICK-only and never typed into. Wait bound: 200 ms (jev-ultrafast) is a floor, browser-use's 400 ms suggests real sites need more; make it configurable per job.

**5. `getFullAXTree` vs `getPartialAXTree`.** Draft A proposes `getPartialAXTree{objectId|backendNodeId, fetchRelatives:false}` on demand; Draft B proposes `getFullAXTree` only for diagnostics and `getPartialAXTree{backendNodeId}` as a cross-check. Protocol JSON confirms both are experimental and that `getPartialAXTree` accepts `nodeId | backendNodeId | objectId` and `fetchRelatives`. **Resolution:** the distinction matters for cost, not fidelity: per-element `getPartialAXTree` is one small call when needed; `getFullAXTree` is per-frame and large. Use `getPartialAXTree` for name cross-checks and evidence; use `getFullAXTree` only as an optional diagnostic capture. Whether either flattens open shadow DOM in Chromium 152 is unverified (both drafts inferred it).

**6. jev-ultrafast line citations.** Draft A's `model.py` ranges (71-86, 89-104, 140-192, 219-257) do not exist in the 198-line file; Draft B's (12-27, 30-45, 81-117, 126, 160-198) match. Draft A's `questions.py:14-17` for TARGET should be 16-19. Draft A's other repo citations (`design.md`, `snapshot.js`, `browser.py`, `agent.py`, `performance.md`) are correct. The synthesis uses the judge's line numbers.

**7. Selection mechanism in manuvra-chrome.** Both drafts describe the selectAll-via-`commands` path as the mechanism to reuse; in fact manuvra-chrome uses `this.select()` via `Runtime.callFunctionOn` (`page.rs:444`). Both are viable; the report records both and their coverage gap (contenteditable).

**8. Batching figures.** `primitives.md:442` says 11.5x/9.6x; the parallel-questions cookbook says 12.2x/10.0x. Minor inconsistency inside the TypeSafe docs; no bearing on the design.

**Rejected or downgraded claims.** Draft B's Puppeteer/insertText inference (rejected, see 3). Draft A's characterisation of tokio as a new dependency (corrected). Draft B's "GET /v1/models path inferred" (upgraded: documented in `models.md:60`). Both drafts' Wayland flag statements (`--ozone-platform=wayland` / `--ozone-platform-hint=auto`) are unsourced inferences and stay unresolved.

## Conclusion and practical implications for the product design

1. **Driver:** extend `manuvra-chrome` (blocking transport, journal, never-kill launch). Add a thin typed layer only for the ~15 methods used; keep raw JSON for experimental domains (`Accessibility`, `DOMSnapshot`, `Input.insertText`, `dispatchKeyEvent.commands`) and pin Chromium 152 in tests. Do not port to tokio in v1; record the decision as reversible.
2. **Jev client:** hand-written serde models, SDK-equivalent retry policy (2 retries, 0.5→5 s, 25 % jitter, 408/429/5xx, honour `Retry-After`/`retry-after-ms`, 10 s per attempt, overall deadline), `validate_choice` in code, `x-typesafe-request-id` in evidence, `jev-1.13.0` pinned once thresholds are tuned. `reqwest` if inside the existing tokio daemon, `ureq` if on a blocking thread.
3. **Decision loop:** one request per observation; speculative heads `operation`, `<op>_target`, `value_for_type`, `step_done`, expectation Nouls; consume only consistent heads; all comparisons and format choices in code; risk-scaled per-head gates tuned on recorded runs; WAIT once then BLOCKED with distributions; independent done-condition verification.
4. **Observation:** injected snapshot with Playwright-quality names and open-shadow/slot traversal, per-frame injection for same-origin iframes, freshness guards and act-time geometry/occlusion recheck; `DOM.describeNode` → `backendNodeId` → `getPartialAXTree` as cross-check and evidence; AX tree never the primary input.
5. **Typing:** caller value map, Jev picks the name; click → select-all → `insertText` → read-back; setter+events only for structured input types and `<select>`; per-key fallback available from v1; comboboxes as a two-phase type-then-click flow; CLICK-only for ARIA listbox/menu/date-grid widgets; `missing_value`, `malformed_value`, `typed_mismatch` as first-class verdict reasons.
6. **Spikes to schedule before freezing the design:** insertText/`beforeinput` on React editors; shadow DOM and iframe fixtures for the snapshot script vs AX tree; Wayland launch flags; a recorded-run A/B on value-head shape.
